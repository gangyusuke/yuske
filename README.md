# スマホ副業AIエージェント

スマホだけで完結できる副業を提案し、月10万円の収入を目指すための計画を一緒に
考えるAIエージェントです。Claude API（Anthropic SDK）を使い、ユーザーの状況を
ヒアリングしながら現実的な副業プランと収入試算を提示します。

## 構成

- `server.js` — Express製のバックエンド。Claude APIとの対話・ツール呼び出し
  （収入計算）を行うエージェントループを実装。
- `public/` — スマホブラウザ向けのチャットUI（素のHTML/CSS/JS）。
- 会話履歴はサーバーのメモリ上にセッションIDごとに保持（永続化はしません）。

## セットアップ

```bash
npm install
cp .env.example .env
# .env に自分の ANTHROPIC_API_KEY を設定
npm start
```

ブラウザ（スマホ推奨）で `http://localhost:3000` にアクセスしてください。

## 使い方

1. 1日に使える作業時間や興味のある分野をチャットで伝える
2. エージェントが必要に応じて質問しつつ、スマホ完結型の副業を提案
3. 目標月収（デフォルト10万円）に対して必要な稼働時間・時給をツール計算で提示
4. 「おすすめの副業」「1日の稼働時間の目安」「月10万円到達までのステップ」をまとめて回答

## 注意事項

- 収益を保証するものではありません。あくまで計画づくりの補助ツールです。
- `ANTHROPIC_API_KEY` は `.env` にのみ保存し、リポジトリにコミットしないでください。

# Meta/TikTok縦型アフィリエイト運用（リビンマッチ）

上記の副業エージェントとは別に、本リポジトリには **Meta/TikTok縦型動画広告を
使ったアフィリエイト（メディアバイイング型）運用**の設計ドキュメントと、
Claude Codeのサブエージェント/スラッシュコマンド基盤が同居している。

外部サービスへの実接続・課金・広告入稿は一切行わない。詳細は `CLAUDE.md` を
起点に `docs/` 配下を参照。全体の業務フローは `docs/05_workflow.md`、
案件情報・許容CPA・NG表現・撤退基準は `CLAUDE.md` に集約されている。

## ドキュメント地図

`CLAUDE.md` 参照。主要ファイルは `docs/00_assumptions.md`〜`docs/07_reporting.md`、
`data/creatives.csv`（クリエイティブ管理台帳）、`scripts/analyze.py`（撤退基準判定）。

## 初動7日間チェックリスト

出稿を開始する前に、以下の順で進める。**🔒が付いた項目は自動化しない工程で、
必ず人間（自分）が行う。**

### Day 1：ASPへの確認事項送信（最優先）🔒
- [ ] `docs/01_offers.md` #0 の質問テンプレート（許可媒体にInstagram/TikTokが
      含まれるか、直リンクの対象範囲、増枠交渉条件、記事確認の審査日数等）を
      そのままコピペしてASP担当者に送信する
- [ ] 広告費・ツール費用の決済手段（クレジットカード等）を確認する
- [ ] Meta Business Managerのビジネス認証状況を確認する（→ docs/06_accounts.md）

### Day 2：クリエイティブのドラフトを整える
- [ ] `/new-creative` で不足している訴求軸のフックを追加生成する
- [ ] `docs/03_creative.md` の絵コンテ2本を確認し、撮影に必要な小道具・
      ロケーション・演者を手配する
- [ ] `/check` で全ドラフト（`data/creatives.csv` の `status=draft` 行）を
      一次チェックする

### Day 3：ASP回答の反映
- [ ] ASPからの回答を `docs/01_offers.md` #0・`docs/00_assumptions.md` #13〜16に
      反映する（許可媒体がFB限定でTikTok/Instagram NGだった場合は、
      配信媒体の見直しが必要になる点に注意）
- [ ] 「営業電話なし」等、ASP確認が取れていない断定表現が台本に残っていないか
      再確認する

### Day 4〜5：撮影・編集
- [ ] 絵コンテに沿ってスマホで撮影する（本格機材は必須ではない）🔒
- [ ] 編集・テロップ入れを行う 🔒
- [ ] 完成した台本・テロップ文言を再度 `/check` に通す

### Day 6：入稿（少額スタート）🔒
- [ ] `docs/04_budget.md` の検証フェーズ（日予算3,000〜5,000円/クリエイティブ、
      同時6〜10本）に沿ってMeta/TikTok広告アカウントに入稿する
- [ ] 1日10件の案件上限に対して十分余裕のある予算設定になっているか確認する

### Day 7：計測体制の準備
- [ ] 媒体の実績エクスポートを `data/raw/` に配置する運用（→ `data/schema.md`）を
      一度手を動かして確認する 🔒
- [ ] `/analyze` を試験的に実行し、`data/creatives.csv` が更新されることを確認する
      （初日はCV0が多く判定は参考程度になる想定）
- [ ] `docs/00_assumptions.md` の未検証事項（特に#13〜21）のうち、
      この1週間で解消できたものにチェックを入れる

### このあとの流れ
2週目以降は `docs/04_budget.md` の検証→拡大→維持フェーズに沿って
`/analyze` の判定（`increase`/`continue`/`decrease`/`stop`）を毎日〜数日おきに
確認し、`/weekly` で出資者向け週次レポートの草案を作成する。
