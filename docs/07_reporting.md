# 出資者向け報告フォーマット

## 1. 報告の目的と原則
出資者（パトロン）は自己資金ではなく他者資金の提供者であり、透明性の高い
定期報告が信頼関係の前提となる。以下を原則とする。

- **数値は`data/creatives.csv`・`scripts/analyze.py`の出力に基づく事実ベースで報告する。**
  見込み・推測を含める場合は必ず「見込み」と明記し、確定値と区別する。
- **悪い情報（撤退基準抵触、赤字クリエイティブ等）も隠さず報告する。**
  月次収支シミュレーション（→ docs/04_budget.md）の悲観ケースに近い状況であれば
  その旨を明記する。
- **報告の作成はAI（`report-writer`）が支援するが、送付は必ず人間が行う**
  （→ docs/05_workflow.md）。

## 2. 報告頻度と粒度

| 種別 | 頻度 | 内容 |
|---|---|---|
| 週次 | 毎週 | 消化額・承認件数・判定サマリー・当週の打ち手（`/weekly`で草案生成） |
| 月次 | 毎月 | 週次の集計＋月間収支（悲観/標準/楽観シミュレーションとの比較）＋翌月方針 |

## 3. フォーマット
`templates/weekly_report.md` を参照。主要項目：
1. サマリー（消化額・承認件数・報酬合計・損益）
2. クリエイティブ別ハイライト（`data/creatives.csv`のverdict別集計）
3. 今週/今月の打ち手（増額・差し替え・停止・新規テスト）
4. リスク・要確認事項（`docs/00_assumptions.md`の未検証事項の進捗を含む）
5. 来週/来月の方針

## 4. 月次収支の見方
`docs/04_budget.md`の悲観／標準／楽観シミュレーションと実績を突き合わせ、
どのケースに近いかを毎月報告する。標準ケースを大きく下回る場合は、
docs/00_assumptions.md #15（Meta/TikTok経由CVRの実測値）を優先的に更新し、
翌月の予算配分（→ docs/04_budget.md 2章）を見直す材料とする。

## 5. 運用ルール
- `/weekly` コマンドが生成するドラフトは `reports/YYYY-MM-DD_weekly.md`
  （または `_monthly.md`）として保存し、Gitで履歴管理する。
- ドラフトは人間が内容を確認・修正してから出資者へ送付する。
- 送付後、実際の反応・追加の資金拠出判断等があれば、次回レポートの
  「来週/来月の方針」に反映する。
